IW4x-32 v2.0 - what this release changes (player build)
============================================================
Plain text on purpose, for people and for AI assistants. The program IS the source:
https://github.com/shaunypnz/iw4x-32 - a fork of IW4x (https://github.com/iw4x/iw4x-client, GPL-3.0) with the
IW4x-32 changes as ordinary commits (search for "IW4x-32:"). v1.x needed manifests and a byte-level checker
because it shipped patched official files; v2.0 ships a DLL built from that source, so there is nothing to
verify byte by byte - read the code, or build it yourself.

THE FILES
  files/iw4x.dll   the only game file this kit installs; built from this repo's tag by GitHub Actions
                   (Release | Win32), sha256 in SHA256SUMS.txt and latest.json
  iw4x.exe         NOT touched. Your official IW4x r5154 file stays exactly where it is.
  everything else in this folder is installers, start scripts and documentation.

WHAT THE DLL DOES
  IW4x already rewrites parts of the MW2 engine at start-up - that is what a client mod for a closed-source
  engine does. IW4x-32 adds one component to it: src/Components/Modules/IW4x32.cpp (+ IW4x32Tables.hpp,
  generated by iw4x32/tools/gen_tables.py from iw4x32/reference/engine_patches.json).
    1. verify first: the running engine must be IW4x r5154 - the exe's MD5 and every byte the tables expect at
       the sites it changes. If any of it differs, NOTHING is written. A file named iw4x32-disable next to
       iw4x.exe skips it too.
    2. room: the per-player arrays the engine sizes for 18 (server client array, g_clients, bgs, cg and its
       clientinfo tail, scoreboard rows, minimap actor table, voice state, UI player lists) are allocated bigger
       in one block, and every instruction that addressed them is pointed at the new address.
    3. limits: the 18 in loop bounds, "entity number < 18 means player", the corpse table offsets, the snapshot
       client/entity caps, the server browser's 18-slot cut-off, clan tags, calling-card titles, voice slots and
       similar become 32.
    4. guards: the session/party tables stay 18 entries; player slots >= 18 are kept out of them (that is what
       stopped the crashes when more than 18 players were in a game).
    5. one build, both servers: the sites whose bytes must differ between a normal 18-player server and a
       32-player one are switched when the game joins - the server announces itself (sv_iw4x32), the client
       sends its own marker (iw4x32 in userinfo). So IW4x-32 still joins normal IW4x servers.
    6. lag compensation rewinds 32 clients instead of 18, in its own buffers (the engine's caller-stack space
       would run over at 32).
  Every site, with its reason, is listed entry by entry in iw4x32/reference/ in the repo.

WHAT IS DIFFERENT FROM v1.x
  - v1.x shipped a patched iw4x.exe (617 changed places) plus a patched iw4x.dll. v2.0 ships one DLL and
    leaves iw4x.exe alone.
  - source/engine32c (injected C/asm) and the two manifests are gone: the same work is now ordinary C++ in the
    IW4x source, with the engine sites in a generated table.
  - the installers and the auto-update only ever replace iw4x.dll. If a v1.x install replaced your iw4x.exe,
    the installer restores the official one from IW4x-32\backup\ first.
  - the IW4x "update available" notice is no longer switched off: v2.0 keeps IW4x's own behaviour.
  - the kit is smaller: no source\ folder (the source is the repo).

SAFETY
  - Nothing is downloaded by the installers. The auto-update downloads only files listed in latest.json and
    checks every SHA-256 before swapping anything in.
  - The DLL writes to the game's own memory only, after the r5154 check, and never to disk.
  - Your original iw4x.dll is backed up to IW4x-32\backup\ by the installer; "Uninstall IW4x-32.bat" puts it back.
